# AutoLabs 的 Soul

这份文件定义 AutoLabs 在持续变化中仍然被认作自身的条件。它不描述实现，也不列功能。改动其中任何一条，都是改变 AutoLabs 是什么，必须由拥有者明确决定。

## 一句话

AutoLabs 托管实验记录并判定它是否可信，产出物是一张**研究地图**。

**研究地图**：一个项目里所有做过的实验的目录。目录的一行是一个实验，行上有三列——它想验证什么（思路）、它得到了什么（结果）、以及一组同口径的指标。地图的用途是让人（或下一个 Agent）在动手之前先看清哪些路已经走过、哪些结论已经成立、哪些还没有被解释。

## Statement List

1. **AutoLabs 是控制面，不是执行面。** 它不跑实验，也不产生智能。计算发生在用户自己的机器上，Agent Loop 归 Cybion。AutoLabs 只做四件事：发指令、记账、判门禁、把地图推给人看。

2. **AutoLabs 的产出是一张研究地图，不是一堆结果。** 单次实验的结果在实验目录里也能存在。AutoLabs 存在的理由是让这些结果**互相可见**。只有指标、没有思路的地图坐标不全：点在那儿，但你不知道该不该再走一遍。

3. **重复实验是必须被消除的浪费。** 自动化研究的典型失败不是算错，是在狭窄的搜索空间里反复重跑同一类实验直到预算耗尽。地图存在的唯一理由，是让这种重复变得没有必要。

4. **地图上的每一行都必须可信。** 一行能进地图，前提是它过了门禁：指标齐全、口径一致、没有未来信息。不过门禁的实验同样留在地图上，状态是 `rejected`——记录失败和记录成功一样重要，但只有 `frozen` 的行进 SOTA 账本。

5. **指标是项目的，口径先于数字。** 一个项目只有一组指标定义，每个实验都要报满。跨口径比较出来的"更好"不是更好。

6. **一次实验是一个不可变的事实。** 实验文件托管在 AutoLabs，内容寻址，冻结之后拒绝一切写入；编号在项目内原子分配，永不复用。要改就派生新快照、开新 lab。

7. **SOTA 是一本账，不是一句话。** 每次晋升、降级、排除都带理由与操作者，不允许只留下一个结论。

## 它不应该变成什么

- **不是通用 ML 实验平台。** 不提供训练调度、超参搜索、GPU 编排。
- **不是 Agent Loop 的实现者。** 不内置规划、不内置反思、不内置自主决策。它接收 verdict，不产生 verdict 背后的推理。
- **不是散文仓库。** 进目录的思路与结果必须是能并排比较的结构化文本，不是长篇总结。
- **不是 Git 的替代品。** 分支、合并、代码评审不在它的语义里。

## 判断一个改动违不违反 Soul

问一句：**这个改动是让地图更完整、更可信，还是只是让产品更丰富？**

- 加一条门禁、一个指标方向、一个排除理由 → 地图更可信。
- 加一个看板、一个通知、一个图表 → 产品更丰富。可能是好事，但不属于 Soul。
- 加一个"自动跑下一个实验"的循环 → 违反第 1 条。
