# ADR 0007：研究循环没有人在环

日期：2026-11-08

## 背景

上一版把「出主意」做成了建议：master thread 写好思路，填进表单，人点「创建」才发出。这仍然是人在环——每一轮都要有人按一下，研究节奏由人的注意力决定，而不是由证据决定。

## 决定

1. 项目上有 `loop_state`：`running` / `paused`。界面上只有两个动作——**启动研究**、**暂停研究**。
2. 启动之后 AutoLabs 自己转：master thread 读地图出思路 → 用它开一轮实验并发出去 → 等执行体回传结论 → 再出思路。中间没有确认步骤。
3. 每一拍都从数据库重新判断「现在该做什么」（`decideLoopAction`），所以 cron 每分钟一拍、启动时立刻一拍，重复执行都安全：手里有没结算的实验就等，有思路就发，没有就请它出主意。
4. 暂停只做一件事：**不再开新实验**。在飞的那一轮照常跑完、照常结算——正在跑的计算不该因为暂停而被砍掉。
5. 循环自己出错（开不出 Thread、没有快照、Cybion 报错）就暂停并把原因写进 `loop_error`：与其每分钟重试烧一堆请求，不如停下来把话说明白。

## 为什么用 cron 而不是 Workflows

一拍的全部工作就是读几行状态、最多发一次请求；没有长任务、不需要睡眠。cron 每分钟一拍的心跳足够，而且失败可见、重放安全。等出现「需要在一拍里等几分钟」的活，再换 Workflows 不迟。

## 边界

- 循环不判断思路好坏：那是 master thread 的事。循环只负责不让研究停在「等人按按钮」。
- 循环不取消在飞的 Thread：暂停是「不再开新的」，不是「把正在跑的砍掉」。
- 每轮实验仍然走 `openRun` + `startRunThread`，和界面上手开一轮是同一条代码路径。
