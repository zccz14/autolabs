# ADR 0006：Cybion 凭据由后台静默维护，不是用户要管的东西

日期：2026-11-08

## 背景

ADR 0004 把「用当前登录换一把 Cybion API key」做成了工作台上的一张卡片，放在项目列表最上面：显示是「自己的 key / 服务级 key」、前缀、创建时间，还带「用当前登录换一把」和「吊销」两个按钮。

用起来才发现这块是纯认知负担：

- 它讲的是平台自己的事。用户来这里是管研究地图的，不需要知道 AutoLabs 用什么身份在 Cybion 里开 Thread，也不需要知道 key 的前缀和到期时间。
- 它拦在第一次开实验的路上。「还没换过 / 换一把」看起来像一个必须做出的选择，而实际上无论点不点，平台都能把这一轮发出去。
- 换过之后它仍然占着首页最显眼的一行，每次进来都要被读一遍——信息却是恒定的。
- 「吊销」这个按钮是它招来的：一个用户不会主动想吊销的东西，先给了他一个管理界面，再要求他理解后果。

## 决定

1. **界面上没有 Cybion 凭据**：没有卡片、没有按钮、没有状态、没有错误提示。它不再是产品的一个名词。
2. **后台按需 ensure**：真正要用 key 的那一刻（开 Thread、发第一条输入、读思路线程的回复），如果这个人名下还没有 key，就用这次请求里本来就带着的登录 JWT 换一把、密封存下来，然后继续。用户看到的只是「发出去了」。
3. **失效自愈**：Cybion 回 401 说明这把 key 不认了（被吊销、被轮换），当场再换一把并把这次调用重做一遍，最多一次。一次 key 的意外不该表现为一轮实验失败。
4. **换不到就兜底**：没有登录 JWT（机器凭据上报）、登录没带 `cybion.ntnl.io` audience、没有 `CREDENTIALS_KEY`、或换取本身失败，都回退到 Worker 里的服务级 `CYBION_API_KEY`；只有连它也没有才报错，且错误里写清缺什么。
5. **删掉 `/api/v1/cybion/credentials` 三个端点**：凭据不是这个产品的对外对象，留一个没人调的 API 只是另一种认知负担。

## 代价

- dispatch 的第一跳可能多一次到 Cybion 的往返（每人只有一次，之后都用存下来的 key）。
- 界面不再有「吊销」入口。要断开一次授权，得去 Cybion 的令牌列表把那条 `AutoLabs` 删掉；删掉之后 AutoLabs 下次会自己再换一把——这是「智能体自己维护自己」的必然代价，断开关系应该发生在授权方（Cybion）而不是使用方。
- 401 自愈会让一次失败的调用重试一次，失败原因只留在 `warn` 日志里，界面依旧只说「发出去了 / 没发出去」。
- 换取失败而回退服务级 key 时，Thread 会落在部署者账号下而不是操作者账号下。这条兜底路径现在只有日志可见，是有意为之：宁可跑起来，也不要因为一次换取失败挡住实验。
