# ADR 0008：执行体用 Cybion 签的 Thread 令牌，不再收 AutoLabs 的长期凭据

日期：2026-11-09

> 取代 ADR 0004 第 2 条（「签发一把只覆盖 read/write/verdict、30 天到期的项目凭据」）与 ADR 0005 里思路线程的只读令牌。两者都说的是把一把长期凭据塞进第一条输入。

## 背景

派单简报里原来有两把凭据：

- 每轮一把 `alb_…`，覆盖 `read/write/verdict`，30 天到期；
- 每个项目的思路线程一把 `alb_…`，只读，30 天到期。

两把都是「写进对话里的长期秘密」。Thread 历史会被共享、导出、回放，也会被模型复述；而它们的有效期是 30 天，泄漏之后唯一的补救是有人记得去吊销——但界面上连「谁在用这把」都看不出来。

Cybion 现在给每条 Thread 一个身份：`create_thread_token` 签一张 60 秒有效、`sub` 就是当前 Thread 的 JWT，公钥发布在 `/.well-known/jwks.json`。这正好是执行体需要的东西——它要证明的不是「我是某个项目的机器」，而是「我是你派出去的那条 Thread」。

## 决定

1. **AutoLabs 不再往简报里放任何凭据。** 派单与思路简报都改成一句话：需要调用时先 `create_thread_token` 现签一张，60 秒内有效，401 就再签一张。
2. **验签在 `authenticate` 里加第三种身份 `kind: 'thread'`。** 按 `iss` 分流：`https://cybion.ntnl.io` 走 Cybion 的 JWKS（EdDSA），其余照旧走 Auth Mini。两条路径各自完整验签，谁也不信未验证的 claim。
3. **授权仍然只看 AutoLabs 自己的表。** `sub` 拿回来之后：命中 `runs.cybion_thread_id` 就是那一轮的执行体（read/write/verdict，且只能操作这一轮），命中 `projects.idea_thread_id` 就是思路线程（read）。令牌不携带权限，也不携带项目。
4. **手工项目凭据接口保留。** `POST /api/v1/projects/{slug}/tokens` 仍可以给人自己的脚本签一把长期凭据——那是人明确做出的决定，不是平台塞进对话里的东西。没有任何 agent 流程再用它。

## 代价

- 一次签一张：跑一轮实验里要读文件、传产物、报结论，会在不同时刻签几次。每次多一条工具记录，换掉的是一段不会被复用的凭据。
- 60 秒比原来紧：Agent 如果签完先去做别的事，回来就过期了。简报因此明确写了顺序——先准备好内容，再签，再发。
- JWKS 成了对外依赖：Cybion 不可用时执行体签不出令牌，`jose` 那边缓存过期后也验不了。这是「把长期秘密换成短命声明」必须付的账；换来的是令牌进档案不再等于凭证泄漏。
- 老的 `alb_` 凭据还留在 `project_tokens` 里，但派单与思路线程都不再发；想让它们彻底消失，把行删掉即可。
