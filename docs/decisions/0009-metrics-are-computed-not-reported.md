# ADR 0009：指标由程序算出来，执行交给 eXe

日期：2026-11-12

> 这一条改的是「谁对第三列负责」。地图的一行有三列：思路、结果、指标。前两列归模型，第三列不归。

## 背景

`POST /runs/{id}/verdict` 里的 `metrics` 由 run thread 自己填。平台只做三件事：key 在不在口径里、必报的缺没缺、是不是有限数字。**它从不复算这个数字。**

于是「跑出一个指标」这件事变成了「一个 AI 模型在对话里写下一个数字」。这不是自动化研究，这是把模型的断言当成实验结果。它有两个直接后果：

- 数字无法复算：换一次执行、换一个模型，没人知道同一个实验会不会给出同一个数；
- 指标看起来依附于模型：因为产出它的确实是模型，而不是那段实验代码。

## 决定

1. **责任边界一次划清。** 思路 Thread 出思路；run thread 只负责「把实验实现出来、跑通冒烟测试、跑通门禁自测」；**指标不由它产出**。数据同步同理，也不该是它的活。
2. **指标由确定性程序产出。** 一段实验代码加上一份钉住的数据集，跑多少次都应该给出同一个数字。这是「指标是项目的、口径先于数字」能够成立的前提。
3. **AutoLabs 仍是控制面，执行交给 eXe。** 它发指令、记账、判门禁；计算发生在用户自己的机器上。这没有违反「不跑实验」：它多了一个发指令的对象，不是多了一层执行。
4. **每个用户一把 eXe 身份。** 地址就是 Ed25519 公钥。设备只认自己 `trust` 列表里的地址，所以 A 用户的身份碰不到 B 用户的机器——这是验签，不是策略。
5. **私钥由 AutoLabs 托管。** 用户从头到尾不碰私钥：它懒生成、用 `CREDENTIALS_KEY` 密封进 `exe_identities`、只在签名那一刻解开。界面上没有导出、备份、找回。用户唯一要做的是把**公开地址**贴进自己机器的 `trust`——那不是管密钥，是给自己机器授权。
6. **信任必须由人加。** eXe 的 Soul 写死了这一条：填地址必须由人自己做，云端不能代劳。AutoLabs 能做的是把地址摆在显眼处、把「没配上」翻译成人话。
7. **绑定即探活。** 登记一台设备时立刻发一条 `true` 过去，回来了才算接上。没有「以为配好了、其实没配上」这种中间状态——那种状态要等到第一次真跑评估才会暴露，代价是一整轮回测。
8. **派发自己记账。** eXe 明确不做审计、不做归档（Soul 第 11 条：`calls` 只活到调用方取走结果为止）。所以每次登记、探活、移除都进 `events`。

## 代价

- **AutoLabs 持有一把能在信任它的机器上执行任意 shell 的钥匙。** 这是无人值守必须付的账：研究循环半夜自己转的时候，没有浏览器替它保管私钥。缓解手段是真的——撤销只需要在设备上删掉那一行 `trust`，开关在设备侧，云端做不了也拦不住。
- **信任关系查不到。** 中继不回答「设备 D 是否信任地址 X」，这是 eXe 有意的设计。所以探活要等到超时才敢说「说不清」，不能一发出就报好。
- **上限是硬的**：一次调用寿命 ≤ 1 小时，`timeout_seconds` 缺省 60 秒，输出 10 MB，结果取走即删（30 分钟兜底清扫）。超过一小时的评估，得让命令自己后台跑完再回报。
- **投递至少一次**：评估命令必须幂等。
- **轮换要逐台重加地址。** 换一把之后，所有设备都不再认 AutoLabs，直到新地址被加进去。

## 这一版做了什么、还没做什么

已落地：每用户身份（懒生成、密封、轮换留痕）、设备登记与探活、`/devices` 页面、派发审计。

还没落地，且是这条 ADR 真正的目的地：

- `verdict` 拆成 `implemented`（run thread 报实验做完了、门禁自测过了）与 `evaluation`（评估器报指标），`metrics` 从 thread 能写的字段里消失；
- 实验包里的**评估入口契约**：一条命令，输入是快照与钉住的数据集，输出是结构化指标。没有它，eXe 只是「能跑 bash」，指标仍然没有来源。
