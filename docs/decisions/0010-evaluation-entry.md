# ADR 0010：评估入口的契约

日期：2026-11-12

> 接 ADR 0009。那一条说的是「指标由程序算」，这一条说的是「那条程序怎么被叫起来、说什么话」。

## 背景

ADR 0009 把责任划清了：run thread 只负责把实验实现出来、跑通冒烟与门禁自测，指标不由它产出。但划线容易，落地要回答一个很具体的问题——**那条算指标的程序，AutoLabs 怎么叫它、怎么听懂它？**

没有这个契约，eXe 只是「能跑 bash」，指标仍然没有来源。

## 决定

1. **评估入口是一条命令。** 最初它是项目级的一条字符串（`projects.eval_command`），由 `projects.eval_device_id` 指定跑在哪台设备上。**这一条已被 ADR 0011 取代**：命令现在优先来自快照根目录的 `lab.json`，项目设置降级成兜底。
2. **输入靠环境变量，不靠参数顺序。** 派发时注入：

   | 变量 | 内容 |
   | --- | --- |
   | `AUTOLABS_RUN_ID` / `AUTOLABS_LAB` / `AUTOLABS_PROJECT` | 这是哪一轮 |
   | `AUTOLABS_SNAPSHOT_URL` | 这一轮输入快照的 tar.gz |
   | `AUTOLABS_SNAPSHOT_TREE` | 快照的 tree sha，钉住「算的是哪份代码」 |
   | `AUTOLABS_TOKEN` | 只读、两小时到期的项目凭据，只够拉这份快照 |
   | `AUTOLABS_DATASET` | 钉住的数据集 `<id>@<digest前16位>`，没绑就是空串 |
   | `AUTOLABS_METRICS` | 这个项目的指标口径：`[{key, unit, direction, version}]` |

3. **输出只有一句话：最后一行是 `{"metrics": {"<key>": <number>}}`。** 前面打多少日志都行，平台从最后一行往上找第一个能解析成这个形状的对象。找不到就明确报错，不静默返回空。
4. **判门禁仍然在平台。** 评估器交的是数字，不是结论：key 必须在项目已定义的口径里，必报的一个不能少，然后平台补 `metrics-reported` 这条门禁。全过 `frozen`，否则 `rejected`。
5. **交棒点从 verdict 挪到 implemented。** `POST /runs/{id}/implemented` 只收 `gates`（自测证据）、`report_md`、`output_files`；payload 里出现 `metrics` 直接 400。全过 → `evaluating`，有一条没过 → `rejected`。
6. **`evaluating` 算「在飞」。** 地图上这一行还没结算，研究循环就不往下走：这时候出下一版思路，等于让思路去看一张缺了最后一行的地图。
7. **失败有次数，不无限重试。** 派不出去或算不出来，5 分钟冷却后重试，三次之后记 `rejected`，evidence 写清原因。项目还没配入口或没选设备不算失败——不烧次数，配好之后下一拍自己就动。
8. **没有评估入口，研究循环不启动。** 循环要自己推进就得自己算得出指标，否则开了实验也结算不了。所以启动前先检查，缺什么直接停下来说清楚。

## 代价

- **一次调用最多跑一小时**（eXe 的调用寿命上限）。更长的回测必须让命令自己后台跑完再回报，或者把一次评估拆开。
- **`AUTOLABS_TOKEN` 在命令行里。** 它在设备上 `ps` 可见。缓解：只读、一个项目、两小时过期；而且这条命令本来就跑在用户自己的机器上。彻底的解法是让评估器自己从本地读凭据，那要求设备上有 AutoLabs 的客户端——现在没有。
- **评估器要自己拉快照、自己解包。** 平台只给 URL 和令牌。
- **一个项目一条命令**（已由 ADR 0011 解决：命令可以跟着快照走）。
- **历史指标只有在同样的命令下才可比**（已由 ADR 0011 解决：`lab.json` 随快照冻结，`runs.eval_command` 记下实际跑的那条）。
