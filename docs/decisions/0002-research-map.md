# ADR 0002：Lab 的元信息是目录层的一等对象

- 状态：已采纳（2026-11-09）
- 决策者：CZ

## 背景

Phase 1 与 1.5 建好的是研究地图的下半张：内容寻址快照、门禁、指标契约、SOTA 账本。上半张——一个实验**想验证什么**、以及它**得到了什么**——没有进入平台：

- **结果**已经有载体：`runs.report_md`，verdict 时写入，Q-Labs 迁移时取每个 lab 的 `README.md` 原文。但它只在 run 详情页里整块呈现，不参与任何列表或比较。
- **思路**没有载体：一个 lab 的假设、设计取舍、为什么排除掉其他做法，只存在于快照里的脚本与注释中，平台不解析、目录不展示。

## 决策

Lab 的元信息（思路 + 结果）是目录层的一等对象，与指标并列为研究地图的一行。具体形态：

- `runs.idea_md`：这个实验想验证什么、为什么这么设计。开 run 时必填，长度有界。
- `runs.report_md`：保持现状，作为结果列。
- 项目详情页提供目录视图：一行一个 lab，并排看到思路、结果与指标，可按状态过滤。

## 理由

自动化研究的失败模式不是算错，是在狭窄的搜索空间里反复重跑同一类实验。要避免它，回看历史的人必须在**同一屏**内同时看到"当初想干什么"和"实际得到了什么"；拆成两个页面就等于没有。

只有指标的地图能告诉你哪个数字最大，不能告诉你哪条路已经走死了。

## 代价

- 约 300 行：一张 `idea_md` 列的 migration、verdict 与开 run 的校验、一个目录页。
- 历史数据回填只能靠迁移脚本从 lab README 里抽，抽不出来的留空，不猜。

## 不重建的部分

不做富文本编辑器、不做评论线程、不做标签体系。思路是一段有界的 Markdown，它的价值在于被目录化，不在于被编辑。
