# ADR 0013：一键复算整条实验线

日期：2026-11-12

> 接 ADR 0011：算法跟着快照走之后，「复算历史」第一次有了确定的意思。这一条说的是怎么让它一键发生。

## 背景

`lab.json` 随快照冻结之后，一条历史实验的算法是钉死的：同一份代码、同一个入口、同一份数据 digest。那就可以真的重算一遍。

但复算有个陷阱：**如果复算会改写已经记下的数字，整张榜就没人敢信了。** 一个数字被后来的执行悄悄换掉，它就不再是事实，而是一个可以被更新的缓存。

## 决定

1. **复算不改任何已经记下的东西。** 它只产出一份核对结果：`matched` / `diverged` / `failed`，外加复算出来的数字本体（`recheck_metrics_json`）。`metrics_json` 永远不动。

2. **三种结局都有用**：
   - `matched`：这条数字从今往后有了一份「可复现」的证据；
   - `diverged`：**这本身是结论**——口径或环境里有一处没被钉住。页面会点名哪个 key 从多少变成多少；
   - `failed`：这一轮算不出来，通常因为包不符合规范。

3. **一键触发**：`POST /projects/{slug}/recheck` 把这个项目里所有已结算（`frozen` / `rejected`）的实验排进队列。

4. **失败自动进修复通道**：`failed` 的行会被标 `dirty`，走 ADR 0012 的修复。已结算的行修的是「评估树」（`attach-eval-tree`），修完自动重新排队——不用人再点一次。

5. **每拍只派两个**。83 个实验就是 83 次设备调用，一口气砸过去只会把同一台机器打满。

6. **容差 1e-9（相对）**。同一个包、同一个入口，浮点最后一位的抖动不该被判成「不可复现」；差到能被看见的量级才算 `diverged`。

## 代价

- **复算要真花时间**：83 轮 × 一条命令，就算每轮一分钟也要一个多小时，而且全靠 cron 每拍两个推着走。
- **`diverged` 会指出问题，但不解释问题**。它告诉你哪一列变了，为什么变还得人查（版本、环境、随机种子、数据 digest）。
- **老包大多会先 `failed`**：那 83 个实验都还没写 `lab.json`，第一次复算大概率整片标脏，然后靠修复线程一个个补——这是一次性的债。
- **复算结果只留最近一次**。反复复算会覆盖上一次的核对结果，不留历史版本。

## 还没做

- 复算结果的保留策略（现在只留最近一次）。
- 把 `diverged` 变成一条门禁：现在它只是展示，不阻止这一行进 SOTA。
- 复算的批量取消与进度条。
