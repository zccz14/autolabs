# ADR 0005：每个项目一条「思路线程」

日期：2026-11-08

## 背景

开一轮实验过去要人先写思路。写思路恰恰是最需要「读完前面所有实验」的那一步：跑到第 83 个 lab 时，谁也记不住 lab-0054 为什么被排除、lab-0074 的夏普是怎么上去的。人写思路，要么凭印象，要么临时翻目录——两种都会把实验带回已经走过的窄巷。

## 决定

1. **一个项目绑一条 Cybion Thread**（`projects.idea_thread_id`），它是这条研究线的 master thread：读整张研究地图、诊断下一步该往哪走、产出下一轮实验的思路。一个项目只开一条，跨实验长期保留。
2. 点「开新一轮实验」时，AutoLabs 先发一张**地图速览**：状态分布、主指标最好的是哪一轮、每个 lab 一行（状态 + 关键数字 + 一句话思路 + 没过门禁的死因），最近 6 个 lab 给完整叙事，外加指标契约与当前 SOTA。
3. 它只交**一段 Markdown**——下一轮实验的思路，写清要验证什么、为什么这么设计、排除了哪些做法。AutoLabs 取它最后一条 assistant message，填进开 run 表单。
4. 表单里的字**可以改**：思路是建议，开不开这一轮、开成什么样，仍然由人决定。
5. 这条 Thread 属于创建它的人（`projects.idea_thread_user_id`），因为只有那个人的 Cybion 凭据读得到回复。界面上直接给出它的链接，人随时可以进去干预、追问、改主意。

## 为什么是「一条长期的 Thread」而不是「每次现开一条」

诊断这件事依赖记忆：上一轮为什么放弃某条路，只写在它自己的上下文里。每次现开一条，等于每次都让它从零读一遍地图、丢掉上一轮的争论。长期保留的代价是上下文会增长，但这正是 master thread 的意义——它是这条研究线的常驻参谋，不是一次性查询。

## 为什么不是把整张地图倒进去

第一版真的把 83 个实验的全文发了过去：43,103 字符、568 行。这不是「给全」，是给了一坨噪声——读的人抓不住重点，每一轮都要重新读一遍，而且随着 lab 数量线性增长。

现在改成**速览 + 按需取细节**：每个实验一行，细节用一把只读令牌（`idea · <slug>`，30 天到期，每次请求换一把）自己去 `GET /api/v1/projects/<slug>/runs` 或 `GET /api/v1/runs/<id>` 取。地图的体量压在同一个数量级，模型也不必一次读完全部。

## 边界

- AutoLabs 不判断思路好坏，也不替人决定开哪一轮；它只负责把地图给全、把回复取回来。
- 回复必须是对**最近一次请求**的（`idea_request_record_id`）：旧回复不能当成新思路，否则表单会填上上一轮的内容。
- 地图上的叙事被截断：速览一行 60 字、最近几轮 240 字。整篇 README 塞进上下文，读的人也抓不住重点；要全文就走只读接口。
- 证据不足时，提示词允许它交一轮「补数据 / 补诊断」的验证，而不是编一个故事。
