# ADR 0014：实验 Thread 照「线程预设」开，不再只钉一个模型

- 状态：已采纳（2026-11-25）
- 决策者：CZ

## 背景

项目设置里只有 `run_model` 一个字段，开实验时把它作为 `model` 传给 Cybion。一个模型名能决定的只有「谁来跑」，而一条实验 Thread 需要的远不止这些：

- **初始手册**：跑实验的 Thread 该先读哪些手册（交付、代码、量化），决定了它认不认这套规范；
- **推理档位**：同样的模型，档位不同，交付质量差一个档次；
- **预算上限**：一轮实验能烧多少钱，以前只能靠账户默认；
- **上游端点**：模型挂在哪个端点上，模型名本身说不清。

这些在 Cybion 里已经有载体了——线程预设（thread preset）。它是一份设置快照，建 Thread 时整份钉上去，之后改预设也影响不到已经开出去的 Thread。AutoLabs 却在旁边自己维护一个更弱的字段。

## 决策

1. 项目设置从 `run_model` 换成 `run_preset`：存的是 Cybion 线程预设的名字，开实验（以及修复 Thread）时作为 `preset` 传给 `POST /api/threads`。空 = 跟随 Cybion 的账户默认。
2. 保存时核对：拿保存者自己的 key 读一遍 `GET /api/thread-presets`，名字不在里面就当场拒绝，并列出他现有的预设名。
3. 界面不再是自由输入的模型文本框，而是这个人 Cybion 账号里那几条预设的按钮——名字不再靠人记。
4. 预设是账号级的：实验 Thread 跑的是**创建这条 Thread 的人**的预设。项目设置由谁保存，决定的是「用什么名字」，不是「用谁的账号」。

## 后果

- 项目上不再有「模型」这个概念，模型跟着预设走；`projects.run_model` 在迁移 0018 里删掉。
- 名字写错会在保存那一刻失败，而不是等到开实验、研究循环停下来才发现。
- 研究循环自动发起的实验也走同一条路：循环只用得快照，不自己拼设置。
